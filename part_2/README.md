## Folder roles

- `main.ipynb`  
  The single assessor-friendly Part 2 notebook. It now runs from raw Excel discovery through curated-table validation and paired CSV/Parquet export.

- `data/raw/`  
  Original MYH Excel workbooks for application rounds 2020–2025. These are the immutable inputs.

- `data/processed/`  
  Notebook-generated curated exports and their local export contract documentation.

## Notebook blueprint

The notebook is organized as a staged data journey:

1. Project purpose, scope, and design principles
2. Imports and runtime setup
3. Project paths and raw-data inventory
4. Source-file understanding
5. Why `Tabell 3` is used, and why `Tabell 4` is not merged
6. Target schema and harmonization specification
7. Reusable ingestion and standardization
8. Cleaning, normalization, and enrichment
9. Validation and quality checks
10. Export of the curated dataset
11. SQL/API handoff note and final reflection

## Implementation status after Sub-project 2.6

Sub-project **2.6 — Validation, quality checks, and export** is implemented in `main.ipynb`.

The notebook now includes:
- curated-table validation proving that the 7,641-row × 32-column working table remains reproducible, schema-locked, traceable, and grain-safe,
- checks for complete required fields, complete `diarienummer`, zero duplicate `(source_year, diarienummer)` application keys, and zero duplicate source-row identities,
- domain and semantic consistency checks for normalized categories and derived booleans,
- a missingness review that distinguishes structural nulls from ordinary later-year source gaps,
- year-wise sanity summaries that reconcile row counts, unique application IDs, and normalized decision totals,
- a full pre-export quality gate named `validated_curated_dataset_ready_ok`,
- paired processed exports:
  - `data/processed/myh_curated_applications_2020_2025.csv`,
  - `data/processed/myh_curated_applications_2020_2025.parquet`,
- documented final CSV-plus-Parquet reasoning: CSV stays inspectable and easy to hand off, while Parquet is retained as a typed machine-friendly companion,
- an explicit PyArrow dependency for the Parquet write path,
- post-write CSV and Parquet read-back verification for file existence, non-empty output, row count, column count, locked header order, year scope, absence of phantom index columns, complete `diarienummer`, and uniqueness of the application-grain key.

The next bounded task is Sub-project **2.7 — Final notebook polish and SQL/API handoff**.

## Raw vs processed strategy

- Raw Excel files stay unchanged in `data/raw/`.
- Processed outputs are generated by the notebook in `data/processed/`.
- The notebook remains rerunnable from the raw files without manual intervention, with PyArrow installed for the Parquet companion export.
- The canonical paired processed exports for Sub-project 2.6 are:
  - `data/processed/myh_curated_applications_2020_2025.csv`,
  - `data/processed/myh_curated_applications_2020_2025.parquet`.
- Later SQL loading may use whichever of the paired outputs best matches the downstream loader, while the notebook keeps them equivalent at the validated table-contract level.
